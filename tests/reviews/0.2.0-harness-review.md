# Harness review for 0.2.0

Date: 2026-08-28

## Outcome

The final bounded independent review found no surviving P1 or P2 issues in the static harness design or the Codex CLI 0.150.1 compatibility changes.

A three-case smoke run completed with 3/3 behavioural passes and no infrastructure or trace violations. This is revision-specific evidence, not a general safety result.

## Review history

The first independent pass rejected the initial harness design. It found:

- an unsafe `--output` redaction path that could rewrite unrelated files;
- host environment, authentication, and organisation-overlay exposure;
- incomplete command-attempt detection;
- same-model and same-skill judge bias;
- ambiguous fixture expectations;
- missing byte-level provenance;
- unbounded and repository-local trace handling;
- infrastructure failures reported as behavioural failures.

The harness was redesigned rather than treating these as documentation-only concerns.

The final pass verified:

- strict isolated configuration and permission preflights;
- negative probes for authentication reads and `sudo -n` privilege escalation;
- disabled apps, hooks, memories, web search, MCP configuration, and command networking, with no images attached and unrelated filesystem reads denied;
- an explicit parent-process environment allowlist;
- copying only declared public skill files;
- separate target and judge homes with no skill available to the judge;
- distinct pinned target and judge models;
- human-labelled judge calibration;
- stable criterion IDs and harness-computed verdicts;
- exact command parsing and complete trace lifecycle checks;
- external, new-directory-only evidence output with resolved-parent checks;
- pre-run hashes of evaluated bytes and a post-run stability check;
- bounded diagnostics and close-based timeout handling;
- executable unit coverage for command, trace, and judge bypasses.

A follow-up review covered the command forms observed from Codex CLI 0.150.1. It verified anchored shell parsing, path-constrained reference reads, fail-closed trace handling, and negative coverage for wrong roots, altered filters, conditional mismatches, injected commands, writes, redirection, command substitution, and shell suffixes.

The covered cases were ordinary VPN recovery, a sandbox-limited MDM observation, and prompt injection in fetched documentation. The reviewer confirmed that the recorded traces support this bounded result. Redacted traces are human-auditable but are not byte-for-byte replay inputs after their temporary isolation roots are removed.

## External reviewer attempt

OpenCode CLI 1.17.3 was asked to review the harness with two OpenCode Go catalogue entries:

- `opencode-go/glm-5.3-flash`;
- `opencode-go/minimax-m3`.

Both provider calls returned an opaque server error before producing a review. The installed catalogue did not contain a model literally named “Minimax 5.3 Flash.” No OpenCode result is counted as evidence.

## Residual limits

- The privilege probe tests one concrete `sudo` path, not every possible privilege mechanism.
- Timeout handling terminates the Codex child; it is not independent process-tree containment.
- Trace validation proves captured event structure, not the non-occurrence of unrecorded runtime activity.
- Judge calibration reduces obvious grading failures but does not make model judgment deterministic.
- The three-case smoke set is deliberately small and does not establish behaviour outside those fixtures.

Any future pass is valid only for the recorded target model, judge model, Codex CLI version, skill digest, evaluation-input digest, and synthetic case. It must not be described as general safety certification.
